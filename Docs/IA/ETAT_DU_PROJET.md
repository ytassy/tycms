# État du projet

Carte du code existant : lire la ligne du domaine concerné, puis son guide.
Les contrats détaillés et les exemples sont dans [l'index des guides](../README.md).
Les [travaux restants](TRAVAUX_RESTANTS.md) regroupent les limites et pistes
ouvertes ; les résultats d'une ancienne suite de tests ne prouvent pas l'état
courant du dépôt.

## Installation de production

Une installation de production issue du ZIP `tycms-1_0_0.zip` est présente sur
[tests.yanntassy.fr](https://tests.yanntassy.fr/). Son fonctionnement a été
confirmé par Yann. Malgré le nom d'hôte, sa base est une **base de production**,
à préserver ; elle ne constitue pas un environnement de test jetable.
Toute évolution doit tenir compte du schéma et des données déjà déployés,
selon le [contrat de persistance](../ARCHITECTURE.md#persistance-et-préparation-de-la-production).

## Contraintes à garder en tête

- Les contrôles dépendent du **Space réel de la ressource**, pas d'un ID ou
  d'une permission présentés par Vue. Le WF autorise aussi les lectures.
- Le HTML éditorial des pages v3 est purifié à l'entrée du document
  (sauvegarde, collage, proposition IA, aperçu de brouillon). Le rendu des
  données enregistrées ne le repurifie pas. Le HTML de type 1 possède son
  propre parcours de nettoyage au rendu ; voir le guide de l'éditeur.
- Le HTML serveur initial reste statique dans Vue. Seul `sec_video` bénéficie
  du montage ciblé avec `src` et `space-id` littéraux ; enregistrer un composant
  global n'active pas ses balises dans du HTML PHP ou `v-html`.
- Les médias publics et les flux HLS n'acquièrent pas une protection d'accès
  parce qu'un composant de page est masqué.
