# SEC-003 — Grammaire meta refresh dans Symfony HtmlSanitizer

État : vérifiée localement — version affectée remplacée ; production non vérifiée.
Lots : 02, 09. Révision initiale : `df84bd5a9bf9e56766bb380471d7a101a69907d0`.
Classement projet : renforcement ; redirection ou XSS applicative non démontrée.
Confiance : forte sur la version et l'exclusion de `meta` dans les profils lus.

## Comportement, preuve et protections

Avis [GHSA-wm2w-4mgj-vw33](https://github.com/symfony/symfony/security/advisories/GHSA-wm2w-4mgj-vw33),
`CVE-2026-121373`, `PKSA-4z5q-y2w8-bwqq`. HtmlSanitizer 8.1.8 utilise une
reconnaissance incomplète de la grammaire navigateur de `meta refresh`.
L'exploitation suppose qu'un acteur puisse faire traiter du HTML non fiable
par un profil qui autorise cet élément et compte sur ce contrôle d'URL.

`framework/Lib/HtmlSanitizer/HtmlSanitizer.php:45–91` et
`Core/Helper/Mail/EmailTemplateContent.php:153–168`, sous `src/releases/vdev`,
n'autorisent pas `meta`. La sonde de rafraîchissement est retirée par ces deux
profils avant/après correction. Cette sonde ciblée ne teste pas toute la
grammaire de l'avis ni tous les rendus du projet dans un navigateur.

Preuves : [audit initial](../../Evidence/LOT-02/composer-audit.json),
[sondes avant](../../Evidence/LOT-02/applicability.json) et
[après](../../Evidence/LOT-02/applicability-after.json).

## Décision, correction et vérification

Option compatible autorisée par Yann : **HtmlSanitizer 8.1.11**. Conserver
8.1.8 aurait laissé la sécurité dépendre des seuls profils actuels ; aucun
nouvel élément HTML ni changement de contrat éditorial n'a été introduit.

L'avis disparaît de l'audit Composer, les sondes et les tests HTML/e-mail
ciblés réussissent ; [résultats](../../Evidence/LOT-02/verification.json).
Réouvrir pour une nouvelle autorisation de `meta`, une régression ou un retour
à une version affectée ; l'analyse générale des rendus reste au lot 09.
