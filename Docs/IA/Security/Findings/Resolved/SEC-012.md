État : corrigé et vérifié localement ; déploiement non vérifié.
Lots : 03, 08. Référence : CWE-20.

Base des correctifs : `50cdf55d5ead8891835996b9824f5f649e7b5cf3`, arbre propre
au départ ; changements non commités, identifiés par les
[empreintes et contrôles](../../Evidence/LOT-03/Fixes/README.md).
La suite ciblée réussit : **167 tests, 515 assertions**, sans SQL ni accès
réseau. Les preuves initiales ci-dessous restent attachées à leur révision ;
elles ne décrivent plus le comportement corrigé.

Le routeur vérifie la forme avant regex/décodage : aucun tableau ou objet
n'atteint les validateurs scalaires. Les champs JSON attendent une chaîne
sérialisée ; ses structures internes et schémas gardent leur traitement.
Les scalaires légitimes, booléens et paramètres facultatifs sont préservés.
Le runner répond 400 aux erreurs de paramètres avant contrôleur et transaction,
en JSON pour une API, par ErrorPages sinon. Le CSRF API garde sa priorité 403.

`RouterTest` vérifie tableaux/objets pour chaque VarType et valeurs légitimes,
JSON sérialisés compris. `HttpSecurityTest` suit une entrée tableau réelle
jusqu'au refus API 400, sans exécution du contrôleur ni commande SQL.

Limites : émission HTML 400 relue mais non exécutée dans le test, car ErrorPages
termine le script ; aucun test HTTP serveur. Bornes numériques, limites globales
de corps et validation métier restent aux lots 08/16. Réouvrir si une forme
non admise provoque une exception de type au lieu de l'erreur de paramètre.

## Entrée, contrôle et effet initiaux

PHP peut décoder `id[]=22`, ou un champ JSON tableau, sous forme de tableau.
`Request::input()` le transmet sans imposer une forme scalaire, ce qui est
normal pour d'autres paramètres structurés. Le routeur doit ensuite adapter
la validation au type déclaré.

`Router::resolveInputsForRoute()` appelle cependant `preg_match` directement
pour `VarType::INT` (`Router.php:250`) et FLOAT (`Router.php:270`). Un tableau
provoque un `TypeError`, au lieu d'ajouter une erreur de paramètre au résultat.
La résolution précède le hook WAF et le contrôle CSRF du runner. L'exception
remonte au gestionnaire général `Application::executeAndGetResponse()`, qui
prévoit un 500 générique et une journalisation.

La [sonde](../../Evidence/LOT-03/HttpAuditTest.php)
`testAnArrayForAnIntegerEscapesTheNormalParameterErrorList` reproduit le
`TypeError` avec la vraie déclaration `/space/choose`. Le scalaire `22`
reste valide et `abc` donne normalement une erreur de validation.
[Résultat](../../Evidence/LOT-03/probes.json), clé `parametre_tableau`.
Le 500 est déduit du gestionnaire lu ; son émission HTTP n'est pas reproduite.
En configuration debug désactivée, aucune fuite de trace n'est démontrée ici.

## Options initiales

1. **Recommandé :** contrôler la forme des valeurs avant les validateurs
   scalaires, puis produire l'erreur de paramètre habituelle. Revoir aussi les
   entrées STRING/JSON et les conversions ; ne pas convertir aveuglément un
   tableau en chaîne.
2. Déplacer la validation des enveloppes dans Request : changement plus large,
   qui doit préserver les champs JSON/tableaux légitimes et leurs schémas.

L'option 1 est réalisée, avec un statut 400 pour les erreurs de paramètres.
