# SEC-009 — Déconnexion déclenchable par une navigation GET

État : confirmé, en attente de décision.
Lots : 03, 06. Observation : OBS-009. Référence : CWE-352.
Révision : `1aff26d92a78bccc5d66b067f13dd7614f58e6bc`.
Gravité proposée : **faible** ; déconnexion forcée, sans prise de compte prouvée.

## Entrée, effet et limites

`Core/Plugin.php:284` déclare un type de menu `logout` raccordé à GET.
`MenuRouteHelper` enregistre la route depuis les données de menu ; son URL
exacte dépend donc du déploiement. `UserController::logout()` (ligne 31)
retire l'utilisateur et détruit la session sans preuve d'intention.
Le runner n'exige pas de CSRF sur GET et ignore ici `Sec-Fetch-Site`.

Une navigation extérieure vers une URL de déconnexion existante peut donc
forcer la sortie du compte si le navigateur transmet la session. Contrairement
au POST de SEC-008, une navigation principale GET peut transporter un cookie
`SameSite=Lax`. Les chargements d'images ou d'iframes ne sont pas supposés
équivalents et ne sont pas revendiqués comme une reproduction navigateur.
L'impact peut inclure l'interruption du travail ; aucune perte persistée de
données n'a été démontrée.

La [sonde](../../Evidence/LOT-03/HttpAuditTest.php)
`testDynamicGetLogoutDestroysTheSessionWithoutAnIntentionToken` enregistre
une URL factice `/audit-logout` vers le contrôleur réel comme le fait un menu,
avec session en mémoire. Le GET retire le compte 7 et détruit cette session.
[Résultat](../../Evidence/LOT-03/probes.json), clé `logout_get`.
Les URL et menus SQL réels n'ont pas été interrogés.

## Options à choisir

1. **Recommandé :** GET affiche une confirmation ; la déconnexion effective
   passe par POST avec le jeton de session. Préserve les liens de menus avec
   une étape utilisateur supplémentaire.
2. Adapter le composant/menu pour soumettre directement un POST avec CSRF :
   conserve un clic mais exige d'examiner le rendu de tous les types de menus.

Le contrat actuel autorise les GET à effet de bord avec protection propre ;
un jeton dans l'URL serait une autre possibilité, avec gestion des liens,
caches et journaux à peser. Aucune modification n'est décidée ici.
Tester après correction la navigation étrangère sans intention, puis une
déconnexion voulue et le renouvellement de la session invitée.
